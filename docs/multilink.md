# 多连接 BLE HID 实现

## 行为

- 默认 3 个槽位可同时在线，输入目标与在线集合独立。
- `1`/`2`/`n` 只切换输入目标；不调用断开连接、不清理主机加密状态、不清除通知订阅。
- 切换时向旧目标和新目标发送全释放状态；USB 输入合并层要求先松开物理按键，再恢复向新目标转发，防止 Ctrl/鼠标按钮跨主机粘连。
- 选择离线槽位时保留其他连接，暂停转发，不自动回退到另一台电脑。
- 空槽位的配对窗口与当前连接分开管理。已配对主机回连时始终认领自己的原槽位，不再因为输入目标是另一个空槽位而被拒绝。
- `X` 只删除选中槽位；只有认证失败、握手超时、重复占用槽位、显式忘记等异常/管理操作才会断开对应连接。

## 实现位置

外部接口仍位于 `ble_switch.h`，USB/按钮层不需要知道 GATT 句柄或连接 ID。

- `hid_router.c` 为纯 C 路由模块，持有每个连接的授权槽位、加密/挂起/拥塞状态、订阅掩码和待释放报告。通知发送通过内部可替换的函数接口完成，本机测试使用记录通知的适配实现。
- `ble_switch.c` 为 Bluedroid GATTS 实现，替代只保存一个连接的 `esp_hid` 设备实现。只注册一个 GATT 应用，避免旧版多个 GATT 应用导致重复的连接/断开处理。
- CCCD、协议模式、控制点、LED 输出及输入报告读取均为逐连接状态，不能让一个主机修改另一个主机的订阅。CCCD 按槽位保存到独立 NVS 键，兼容旧 `slots` 存储结构。
- 静态属性由 Bluedroid 自动响应；应用只响应动态属性，避免对 AUTO_RSP 属性二次发送 ATT 响应。
- 所有可变 HID 属性的读/写均由栈强制要求加密。已配对主机可能先自行完成加密，此时不一定触发新的 GAP 认证回调；栈校验通过后的动态 ATT 请求也是已加密的可信证据。未知主机仍必须通过认证完成事件和配对窗口检查，不凭 ATT 请求分配槽位。
- 不对所有已配对连接反复调用 SetEncryption。新设备的安全请求串行处理，避免 Bluedroid 内部 SMP 忙状态导致请求被吞或重复认证超时。
- 广播白名单覆盖所有已配对槽位，与输入目标无关。Bluedroid 建连后可能自动恢复广播，所以必须先停止广播并收到停止完成事件，再修改控制器白名单；修改白名单不会断开现有连接。

## 兼容与验证

保留旧固件的设备地址、报告描述符，以及 Battery → Device Information → HID 服务顺序。开发板上验证的 HID 服务为 `0x0034`，键盘/鼠标/多媒体输入值句柄分别为 `0x0040`、`0x004c`、`0x0053`，与两台电脑原有缓存一致。

槽位 2 保留原配对；联调并发认证问题时，栈自动删除过槽位 1 的密钥。已取得用户授权，仅重新配对了槽位 1，没有清空整片 NVS，也没有删除其他设备。

已实测两台 Linux 主机同时在线、加密和订阅，在线切换与选择离线槽位均保持原连接 ID。硬件回归使用 `t` 中性报告：不产生键盘按下或指针位移，第二台电脑用 btmon 计数对应 HID 句柄的通知，验证非目标主机收不到测试通知。工具不保存 HCI 密钥或报告正文。

压力检查已通过三轮打开串口触发复位后的双机回连，每轮 10 个来回周期，合计 60 次在线目标选择，均无切换引发的断连或通知错误。最终固件另通过了 5 个来回周期的检查，以及仅断开/重连电脑 2、电脑 1 保持原连接 ID 的恢复测试。

```sh
python3 test/run_host_tests.py
~/.platformio/penv/bin/python test/check_multilink.py --cycles 5
```

`check_multilink.py` 需要槽位 1/2 已配对且两台蓝牙开启，槽位 3 为空。SSH 指向第二台电脑；可用 `--host` 指定地址，`--skip-hci` 跳过通知抓包，`--skip-reconnect` 跳过最后故意断开/重连电脑 2 的恢复测试。开启串口可能使此开发板复位，测试会等待两台重新连接，不删除配对。恢复测试只对电脑 2 的 BT Switch 执行 Disconnect/Connect，不关闭整台电脑的蓝牙。

## 未验证部分

第三台实际主机、Windows/macOS/移动设备、随机私有地址轮换后的槽位身份匹配，以及接收器供电/Hub/完整 USB 到 BLE 输入链路仍需单独测试。未承诺固定毫秒级延迟；主机挂起、无线拥塞、BLE 连接间隔都会影响输入时延。
